## Attacks (real Redis, throwaway prefix, cleaned: 0 keys left)
- **A1 steal-back → DOUBLE EXECUTION.** A reads entry; after idle, B `reclaim`s it (times_delivered 2); A (stalled, still running) calls
  `touch` → `XPENDING` owner is **A** again. B keeps running too ⇒ the same job runs on two workers, both writing checkpoints and
  statuses. Same problem for `ack`: `XACK` does not check the consumer, so a stale A finishing late removes B's pending entry.
- **A2 rate-limit lockout.** `INCR` and `EXPIRE NX` are separate round-trips; a crash/connection drop between them leaves a counter with
  TTL −1 (reproduced by doing the INCR alone) ⇒ that token+IP is limited forever.

## Required fixes
1. `JobQueue.touch(consumer, entry_id) -> bool` and `JobQueue.ack(consumer, entry_id) -> bool` must be **owner-checked and atomic** via Lua.
   Use this script for touch (judge-verified on fakeredis 2.40.0 *and* real Redis 8.0.5: owner → 1, other → 0):
   ```lua
   local p = redis.call('XPENDING', KEYS[1], ARGV[1], ARGV[3], ARGV[3], 1)
   if p[1] == nil or p[1][2] ~= ARGV[2] then return 0 end
   redis.call('XCLAIM', KEYS[1], ARGV[1], ARGV[2], 0, ARGV[3], 'JUSTID')
   return 1
   ```
   (KEYS[1]=stream, ARGV = group, consumer, entry_id). Ack: same owner check, then `XACK` + `XDEL`, return 1; else return 0 and do nothing.
2. Worker: when `touch` returns False, the job is **lost** to another worker. Add `still_owner: Callable[[], Awaitable[bool]]` to `RunnerDeps`
   (default: always True). The runner checks it before every stage (next to the cancel check); when False it stops immediately and returns
   `"lost"` **without writing any job status, stage row, checkpoint or event**. The worker logs `job.lost` and does not ack.
   A stage already running when ownership is lost finishes, but its result is **not** written (check again right before writing the checkpoint).
3. `rate_limit` atomic via one Lua script: `INCR`; if the TTL is −1 (new key **or** a key left without TTL) set `EXPIRE window`; return
   `{count, ttl}`. Must also repair a pre-existing TTL-less counter (test: seed a key with no TTL → after one call it has a TTL).
4. Tests: steal-back scenario (A loses → A's runner returns "lost" and writes nothing after that point; B finishes; B's ack succeeds; a late A ack returns False
   and B's entry is untouched); ack by non-owner; rate-limit repair. Extend `tests/live/test_queue_live.py` with the steal-back scenario on real Redis.
