## Required fixes
1. `llm/client.py`: `call_tool(..., mode: Literal["tool", "json"] = "tool")`. **json mode**: no `tools`, `format: "json"`, system prompt =
   given system + `"Reply with ONE JSON object only, no prose, matching this JSON Schema exactly (field names and allowed values):\n" + json(prepared schema)`,
   parse with `extract_json`, then the same coerce → validate → repair loop (repair = assistant message + user message with the validation errors,
   still json mode). **Empty-reply fallback in tool mode**: a reply with neither `tool_calls` nor content → the next attempt is made in json mode
   (count it in `attempts`, record `meta.mode_used`). `CallMeta` gains `mode_used`.
2. `analysis/content.py`: use `mode="json"` for the content/window/reduce calls; add "Fill EVERY field; lists must not be empty when the
   transcript supports them" to the prompts; **completeness check** — when the transcript has ≥ 20 segments and any of chapters / entities / claims /
   topics is empty, re-ask once **for the missing sections only** (a sub-model containing just those fields) and merge. Record `completeness`
   (`{section: count}`) and `reasked: [sections]` in `llm_meta`.
3. LLM-facing chapter model: **no nullable float times** — `title, summary, first_seg, last_seg` (segment ids) + `evidence`; times are derived
   from the segments (the post-check already does this). Same rule for key quotes: `seg_ids` only, no model-supplied times.
4. Wire the LLM into the pipeline: `RunnerDeps.llm` + `StageContext.llm` populated by `worker.py` (one `LLMClient` per process, sharing the
   worker's `httpx.AsyncClient`); `pipeline/runner.py` passes it through.
5. Live acceptance (judge): `tests/live/test_content_live.py` passes 3 runs in a row; the judge's completeness probe gets ≥ 5/6 complete.
