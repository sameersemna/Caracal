## Requirements
1. **Mention extraction** (LLM, json mode): input = the speaker-tagged transcript lines (`render_transcript_lines`), metadata, hints; output
   `mentions: [{speaker_label, name, relation: "self_intro"|"addressed"|"referred", seg_ids}]` — "addressed" = another speaker says the name
   to/for this speaker (e.g. "thanks, Anna", "welcome to the show, X"), "referred" = the name is merely talked about (never an identity source).
   Plus per label `role` (`host|guest|interviewer|interviewee|caller|narrator|presenter|preacher|moderator|panelist|other`) and a
   role/context-only `description` (docs/04 §7). For long transcripts send only each speaker's first 40 segments plus the 3 segments before each of
   that speaker's turns (where addressing happens), capped by `LLM_CONTEXT_CHARS`.
2. **Deterministic verification of mentions**: a `self_intro`/`addressed` mention is kept only if the name actually occurs (case/diacritic-
   insensitive, allowing first-name-only matches of a fuller name) in the text of its cited segments, and the cited segments belong to the right
   speaker (self_intro: same label; addressed: a different label, within the 3 segments before the target's turn). Otherwise it is dropped.
3. **Candidate sources and scores** exactly per docs/04 §7 table: self_intro 0.85, addressed 0.6, metadata 0.5 (0.75 in the sole-speaker
   case), voiceprint `match` → similarity, `candidate` → similarity × 0.6, hint 0.7 (`speaker_hints` like `"host: Lex Fridman"` map to the label whose
   role is `host`; a bare `"Lex Fridman"` hint applies to the most-talking speaker only when there is one speaker, otherwise it becomes a candidate
   for every label at 0.4). Names are grouped by normalised form (reuse the repo's `normalise_name`; a first name merges into a full name that
   starts with it when unambiguous).
4. **Fusion**: `confidence = 1 − Π(1 − score_i)` per name, cap 0.98; promote the top name iff it leads the second by ≥ 0.2 **and** is not
   metadata-only (except the sole-speaker case); else `name: null` + ReviewFlag `ambiguous identity` (when ≥ 2 candidates) — returned alongside.
   Each candidate lists its `sources` and `evidence` (`seg:`, `meta:`, `hint:`, `vp:` ids). `known_speaker_id` + `voiceprint_similarity` set from a
   voiceprint `match`. A voiceprint match and a self-intro naming different people → both candidates, no promotion, flag.
5. **Stage `identity`**: skipped per plan; inputs from the align, voiceprint, content and ingest checkpoints + options; output
   `{speakers: [SpeakerIdentity], flags: [ReviewFlag]}`. `talk_time_s`, `share`, `first_seen_s` come from `speaker_stats`.
