## Judge-verified API facts (2026-11-14, your keys)
- **Brave**: `GET https://api.search.brave.com/res/v1/web/search?q=…&count=N&extra_snippets=true`, headers `X-Subscription-Token`,
  `Accept: application/json`. Results at `body.web.results[]` with `title, url, description, extra_snippets[], age, page_age, language, …`.
  `description` contains **HTML tags (`<strong>`) and entities (`&#x27;`)**. Rate-limit headers `x-ratelimit-limit: "50, 0"`,
  `x-ratelimit-remaining`, `x-ratelimit-reset`. **Invalid key → HTTP 422** `{"error":{"code":"SUBSCRIPTION_TOKEN_INVALID"}}` (not 401).
- **Exa**: `POST https://api.exa.ai/search` JSON `{"query", "numResults", "type": "auto", "contents": {"text": {"maxCharacters": 2000}}}`,
  header `x-api-key`. Results `body.results[]` with `id, title, url, text` (Markdown), optional `publishedDate, author`.
  **Costs money**: `costDollars.total` ≈ $0.007 per search. Invalid key → HTTP 401.

## Requirements
1. **`base.py`**: `SearchHit(provider, query, rank, url, title, snippet, published: str | None, text: str | None)` (frozen, JSON-able);
   `SearchProvider` protocol `name`, `async search(query, *, limit) -> list[SearchHit]`; `SearchError(kind: "auth"|"rate_limited"|"unavailable"|"bad_response")`.
   Text hygiene for every field: strip HTML tags, `html.unescape`, collapse whitespace, drop control chars; `snippet` ≤ 500 chars (Brave:
   description + first 2 extra_snippets joined with " … "), `text` ≤ 2 000 chars (Exa only), `title` ≤ 300. URL must be http(s), else the hit is dropped.
2. **`brave.py` / `exa.py`**: exact requests above (httpx, timeout 15 s, never log the key; error bodies never logged in full). Map statuses:
   401/403/**422 with SUBSCRIPTION_TOKEN_INVALID** → `auth`; 429 → `rate_limited` (read `retry-after` / `x-ratelimit-reset`); 5xx / timeout /
   connect → `unavailable`; unparsable → `bad_response`. Exa: record `costDollars.total` into a per-provider cost counter (exposed for job metadata).
3. **`router.py` — `SearchRouter(settings, redis, keys, providers, *, clock, sleep)`**: `async search(query, *, job_id, limit=5) -> SearchResult(hits,
   provider_used, cached, cost_usd)`:
   - **budget**: `INCR` `Keys.search_budget(job_id)` (TTL 1 day) **before** any provider call; over `SEARCH_MAX_QUERIES_PER_JOB` →
     `SearchResult(hits=[], provider_used=None, …)` + log `search.budget_exhausted` (no exception). Cache hits do **not** consume budget.
   - **cache**: `Keys.search(provider, sha1(normalised query + limit))` JSON, TTL `SEARCH_CACHE_TTL_S`; checked in provider order before calling.
   - **order + fallback**: providers in `SEARCH_PROVIDERS` order, skipping ones without a key; `auth` → disable that provider for the process
     (log `search.auth_failed` once) and fall through; `rate_limited` → one retry after the indicated delay (≤ 5 s, injectable sleep), then fall
     through; `unavailable`/`bad_response` → fall through; **empty results** → fall through to the next provider; all failed → empty result.
   - **rate limit**: in-process token bucket per provider (Brave 5 req/s, Exa 2 req/s — conservative), injectable clock.
   - Query normalisation: trim, collapse whitespace, ≤ 400 chars.
4. Nothing in `src/` interpolates web text into prompts here — that is T3.2, which must pass hits through `wrap_data`.
