## Requirements
1. **`services.py` — `class JobService(settings, repos, redis, keys, queue, data_dir)`**: move the business logic out of `api/routes.py` so both
   adapters call the same methods and return the **same pydantic models**: `create_job(source, options, *, ident_hash) -> JobCreated`,
   `create_upload_from_chunks(chunks, filename) -> UploadCreated`, `create_upload_from_base64(b64, filename) -> UploadCreated` (S7: reject when
   `len(b64) * 3 // 4 > 25 MiB` **before** decoding; strict base64 → `invalid_input`), `get_status(job_id) -> JobStatus`,
   `list_jobs(status, limit, cursor) -> JobList`, `transcript(job_id, fmt) -> Transcript JSON | str`, `subtitles(job_id, lang, ext) -> (bytes, media_type)`,
   `cancel_or_delete(job_id, *, delete_artifacts) -> CancelResult | None`, `wait_for_job(job_id, timeout_s, on_progress) -> JobStatus`
   (subscribe-then-snapshot exactly like the SSE stream; returns at terminal state or timeout). Raise `CaracalError` only.
   REST routes become thin wrappers (status codes/headers unchanged — all existing contract tests must still pass).
2. **`mcp/server.py` — `build_mcp(service, settings) -> MCPServer`** with tools (docs/03 §3) that exist after M1:
   `analyze_audio(url?, upload_id?, audio_base64?, filename?, options?, wait_seconds=120 (0–600))`, `get_job(job_id)`,
   `list_jobs(status?, limit=20 (≤50), cursor?)`, `get_transcript(job_id, format="text"|"json"|"srt"|"vtt", lang="source")`,
   `cancel_job(job_id, delete_artifacts=False)`. Exactly one source for `analyze_audio`. While waiting, call `ctx.report_progress` on each progress
   event. Result when done: `{job_id, status:"done", summary:{title, duration_s, languages, transcript_preview (first 1 000 chars)}, links}`; when not
   done in time: `{job_id, status, progress, hint:"call get_job / get_transcript later"}`. All return pydantic models (structured output).
   Tool descriptions are written for an LLM caller: what it does, when to use it, that analysis is asynchronous, which tool to call next.
   `CaracalError` → `ToolError(f"{code}: {message}")` (never a traceback, never input values).
3. **HTTP mount**: `/mcp` via `streamable_http_app(...)` as in the snippet, `stateless_http=True`, `json_response=True`; the sub-app's lifespan runs
   inside the FastAPI lifespan. `AuthBodyLimitMiddleware` must now also protect `/mcp` (bearer **before** any body read; 1 MiB body cap there,
   since `audio_base64` up to 25 MB needs `POST /v1/uploads` instead — say so in the tool description and cap `audio_base64` at **750 KiB decoded**
   over HTTP; the 25 MB limit applies to stdio). The Origin guard stays. `TransportSecuritySettings.allowed_hosts` =
   `localhost:*`-equivalents for 127.0.0.1/localhost on `CARACAL_PORT`, the `CARACAL_PUBLIC_BASE_URL` host:port, and every `CARACAL_ALLOWED_HOSTS` entry;
   `allowed_origins` = the same hosts with `http://` / `https://`.
4. **`caracal mcp-stdio`**: builds real deps (like `serve`) and runs `run_stdio_async()`. Logging stays on stderr; nothing else may write stdout.
5. **Parity test** (`tests/contract/test_parity.py`): encode the docs/03 §0 table as data. For every row available after M1, assert the REST route and
   the MCP tool both exist **and** return equal data for the same fake job (MCP `structured_content` == REST JSON for get_job/list_jobs/transcript).
   Rows for later cards are listed with `pending="T2.3"` etc.; the test fails if a pending row's MCP tool or REST route already exists without the row
   being marked available (so adding one side without the other is caught).
