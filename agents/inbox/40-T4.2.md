## Requirements
1. **`metrics.py`** (pure, unit-tested): `wer(ref_words, hyp_words) -> (errors, ref_len)` with the same normalisation as `caption_agreement`
   (windowed DP is fine); `der(ref_turns, hyp_turns, *, collar=0.25) -> {der, miss, false_alarm, confusion}` with the optimal label mapping
   (Hungarian or brute force for ≤ 8 speakers), collar around reference boundaries; `identity_score(expected, actual)` → per label
   `correct | wrong | missing | abstained` (abstaining = `name null` when the expected answer is "unknown" counts as **correct**);
   `roc(pairs: [(similarity, same: bool)]) -> [(threshold, tpr, fpr)]` + `best_threshold(…, max_fpr=0.01)`.
2. **`cases.json`**: a list of cases `{id, source: {url|path}, expect: {...}}` — at least: TED (reference = YouTube **manual** captions for WER;
   expect speaker "Daniel Levitin"); All Ears English (expect "Lindsay McMahon"); JFK/TED splice built on the fly from `tests/fixtures/audio/jfk.wav`
   + the TED audio segment 20–40 s and 60–75 s (reference turns known from the construction; expect S-labels unnamed, a JFK candidate allowed);
   Caliendo (expect: no name ≥ 0.6 for any label); SoundCloud instrumental (expect music_detected); German news (expect language de and
   `en` subtitles). URLs only — no media committed.
3. **`run_eval.py --base-url … --token-env CARACAL_API_TOKEN [--cases ids] [--out docs/findings/eval-YYYY-MM-DD.md]`**: submits each case through
   the **REST API** of a running server (so it measures the real system), waits for done, fetches report/transcript/subtitles, computes the metrics
   (WER vs the platform's manual captions where available — download them with yt-dlp `--write-subs` into a temp dir, never into the repo), collects
   voiceprint same/different pairs from the diarize checkpoints via the API (`GET /v1/jobs/{id}` links — or add nothing and compute pairs from the
   report's speakers when exposed; if embeddings are not exposed over the API, skip calibration with a clear note), and writes a Markdown report:
   per-case table, aggregates, timings, LLM calls/cost from `/metrics`, and "expectations met: n/m". Exit 0 always (it is a report, not a test);
   `--strict` → exit 1 if any expectation fails.
4. `scripts/eval/README.md`: how to run it against `scripts/live-suite.sh`-style throwaway environments or the production service.

## Accept
- unit: WER (identical → 0; one substitution; insertion/deletion; normalisation), DER (perfect, swapped labels → 0 after mapping, miss, false alarm,
  collar), identity scoring incl. abstention, ROC monotonic and best threshold respects `max_fpr`.
- the judge runs `run_eval.py` against a live throwaway server and commits the produced `docs/findings/eval-<date>.md`.
- gate green.
