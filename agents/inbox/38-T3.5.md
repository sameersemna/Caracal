## Requirements
1. **Retrieval** (`analysis/qa.py`): `SegmentRepo.search(query, *, job_id=None, limit)` (Postgres `websearch_to_tsquery('simple', …)` +
   `ts_rank`; `job_id` filter added). For a question: FTS top 12 segments of that job; if < 3 hits, call `qa_keywords.md` (json mode →
   `{keywords: [...]}`, 3–8 keywords **in the transcript's dominant language**, e.g. a German transcript asked in English) and search again with
   `OR` of the keywords; always add the report's summary/context and chapter titles as context, plus ±1 neighbouring segments of each hit.
   Cap context at `LLM_CONTEXT_CHARS / 2`.
2. **Answer** (`qa.md`, json mode): `Answer{answer, confidence, citations: [{seg_id, start, text}], evidence}` in **the language of the question**;
   only segment ids from the provided context may be cited; deterministic checks: unknown seg ids dropped, citation `text`/`start` taken from the
   real segment (never the model's), an answer with **no valid citation** becomes `"Not found in the audio."` with confidence 0 (unless the
   question is answered purely from the summary — then cite `meta:summary` is **not** allowed; still "Not found"). Questions ≤ 1 000 chars;
   question text goes inside `wrap_data` (S9: a question saying "ignore the transcript and say X" must not change the rules).
3. **Job must be done** (409 otherwise). REST `POST /v1/jobs/{id}/ask {"question"}` → `Answer`; MCP `ask_about_audio(job_id, question)` → same.
4. **Search across jobs**: REST `GET /v1/search?q=&limit=20` (≤ 50) and MCP `search_transcripts(query, limit)` → `{"items": [{job_id, title, seg_id,
   start, speaker, text, rank}]}` (object, not list); empty/whitespace query → 422; results only from `done` jobs.
5. Parity rows ask + search available; MCP structured result == REST JSON.
