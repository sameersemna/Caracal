## Requirements
1. **Order**: the LLM review needs the assembled report, so `review` must see it. Keep the Stage enum order (review before assemble) and make
   `review` build a **draft** report by calling `assemble_report(...)` itself (pure, no files written), review it, and write
   `{flags: [ReviewFlag], llm_meta}`; `assemble` then appends those flags. (Do not change the enum order.)
2. **LLM review** (`review.md`, json mode): input = the draft report **without** transcript text and evidence excerpts (summary, context, chapters,
   speakers, entities, claims + verifications, languages, quality) + 30 sampled transcript lines (`render_transcript_lines`, evenly spaced,
   including the first and last). Output only `flags: [{severity: info|warn|error, field, message}]` describing **inconsistencies**: e.g. summary
   contradicts a contradicted claim, a chapter title not supported by its time range, a speaker name inconsistent with the transcript, a
   language mismatch. The review cannot edit the report. Max 10 flags; `field` must be a top-level Report key or a dotted path into one
   (`speakers.S1.name`, `claims.claim_3`) — others are dropped; messages ≤ 200 chars, no evidence ids invented (strip any).
3. **Skips**: review skipped for depth `quick`, music jobs (reason `"non-speech audio"`), or when the LLM is unavailable (non-fatal).
4. **Deterministic fixes** (verdict 29): the "chapters cover < 80 %" check is skipped for music / non-speech jobs and when the transcript has
   < 20 segments. Add: "a claim marked `contradicted` but the summary repeats it" is **not** deterministic — leave it to the LLM.
5. Flags are de-duplicated by `(field, message)` across plan/content/identity/verify/review/deterministic sources.
