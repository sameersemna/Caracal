## Requirements
1. **Planner** (`analysis/planner.py`): `plan(inputs: PlanInputs, *, llm) -> StagePlan` (docs/04 §2). `PlanInputs` = duration, speech_ratio,
   transcript (for the music rule + first ~3 min), languages, platform metadata, options, `diarizer_available`, `search_configured`.
   Rules run first and are deterministic; each sets a `reasons[stage]` string. **Music rule**: speech time in segments whose text has no
   letters/digits after removing ♪ 🎵 🎶 and `[...]`/`(...)` tags ≥ 70 % → `music_detected=True`, every language span → `und`, skip diarize,
   align, voiceprint, identity, verify, translate. The LLM (`plan.md`, `call_tool` → `ContentProfile`: `likely_genre`, `expected_speakers`,
   `needs_identity`, `checkworthy_domain`) is called **only** when not music and depth ≠ quick; on LLM failure use a default profile and record
   `reasons["profile"] = "llm unavailable"`. The LLM cannot change `run` flags. Output checkpoint = `StagePlan` JSON (+ `music_detected`,
   overridden `languages` when music).
2. **Stages honour the plan**: `diarize`, `align`, `voiceprint`, `content`, `identity`, `verify`, `translate` start by loading the plan checkpoint;
   if `run[stage]` is False → `skipped` with the plan's reason. (identity/verify/translate stay stubs, but the skip check is in place.)
3. **Content analysis** (`analysis/content.py`): `analyse_content(transcript, meta, hints, options, settings, *, llm) -> ContentAnalysis`
   (summary, context, chapters, topics, entities, key_quotes, claims — field shapes = docs/03 §5 types; LLM-facing models alias `type` →
   `entity_type`). Lines via `render_transcript_lines`, metadata via `render_metadata`, hints as `[hint:n]`, each inside `wrap_data(...)`.
   **Map-reduce** when the rendered transcript > `LLM_CONTEXT_CHARS`: windows at segment boundaries (≤ that size, 1-segment overlap) →
   `content_window.md` per window (concurrently, bounded by the client semaphore) → `content_reduce.md` merges, dedupes entities by normalised
   text, keeps claims/quotes with their evidence. **Depth**: quick → summary + context only; standard → all; deep → chapters at finer
   granularity (≈ every 2–4 min vs 5–10) and up to 15 claims.
   Deterministic post-checks: chapters sorted, clamped to [0, duration], overlaps removed, chapter `start`/`end` must match the cited
   segments' time range ±2 s (else re-derived from them); a key quote is kept only if its text fuzzy-matches (difflib ratio ≥ 0.85, after
   normalisation) the concatenated text of its cited segments, and its `start`/`speaker` are taken from the first cited segment; every
   evidence id normalised (typed regex); items with no valid id dropped (validator runs again at assemble).
   **Language**: all generated prose in `CARACAL_REPORT_LANGUAGE`; quotes and entity text verbatim. Prompts say so explicitly.
4. **Prompts**: each starts with the shared guard (via `load_prompt`), explains the DATA blocks, the evidence-id format with an example
   (`seg:12`, `meta:title`), the report language, and "do not invent names, dates or numbers". ≤ 60 lines each. No examples copied from the
   test fixtures (avoid the model parroting them).
5. **Stage `content`** checkpoints the `ContentAnalysis` JSON + `llm_meta` (calls, attempts, coerced, fallback_used, duration_s).
