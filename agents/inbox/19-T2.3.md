## Requirements
0. **Test gap from verdict 18:** a FakeDiarizer scenario where `SPEAKER_01` speaks first → it must become `S1`, `SPEAKER_00` → `S2`, and the
   embeddings/turns/exclusive turns follow the same mapping. (The judge will re-run the `sorted(ordered)` mutation; it must now fail.)
1. **Migration 0002**: `known_speakers` (docs/05 §1, `name_norm` unique) and `voiceprints` (`embedding vector(256)`, FK cascade to
   known_speakers, `job_id` nullable FK **SET NULL** on job delete, `speaker_label`, `created_at`), HNSW index
   `USING hnsw (embedding vector_cosine_ops)`. Downgrade drops both.
2. **`SpeakerRepo`** (Postgres + fake, shared contract cases): `upsert_known(name, notes) -> KnownSpeaker` (normalise: NFKC, casefold, collapse
   whitespace, strip punctuation → `name_norm`; same norm → same row, notes updated if given), `add_voiceprint(known_id, embedding, job_id, label)`,
   `nearest(embedding, k=5) -> list[VoiceMatch(known_speaker_id, name, similarity)]` (similarity = 1 − cosine distance, best per known speaker),
   `list(q=None)` (with `samples` = voiceprint count), `get(id)`, `delete(id) -> int` (voiceprints removed; one transaction). Embedding length ≠ 256
   or non-finite → `invalid_input`.
3. **`speakers/voiceprint.py`**: `classify(similarity, settings) -> "match" | "candidate" | None` (≥ MATCH, ≥ CANDIDATE); `async enroll(service deps,
   job_id, speaker_label, name, notes)`: job must be `done`, the label must exist in the job's diarize checkpoint (else `not_found`), store the
   label's embedding; **never auto-enroll** (no code path outside the explicit API calls this).
4. **`voiceprint` stage**: skipped if diarize was skipped/failed; else for each label `nearest(k=3)` → output
   `{matches: {S1: [{known_speaker_id, name, similarity, class}]}}` (only `match`/`candidate` kept).
5. **API + MCP (parity)**: `GET /v1/speakers?q=`, `POST /v1/speakers/enroll` (`{job_id, speaker_label, name, notes?}` → 201 KnownSpeaker),
   `DELETE /v1/speakers/{id}` (204; `{"deleted": true, "voiceprints_removed": n}` for MCP) and MCP `list_speakers`, `enroll_speaker`,
   `delete_speaker` — all via `JobService`/a `SpeakerService` in `services.py`. Tool descriptions state that enrollment stores biometric voice data
   and should only be done with the person's consent.
