## Requirements
1. **Targets** (`select_targets`): up to 6 (standard) / 15 (deep) checkworthy claims — prefer `kind=fact` with digits, proper names or dates;
   every speaker whose top candidate confidence is in [0.4, 0.9) ("identity confirm"); every speaker with **no** candidates and ≥ 30 s talk time
   ("quote attribution", using its longest segment of ≥ 8 words or its key quote).
2. **Queries** (LLM json mode, `verify_queries.md`): 1–2 queries per target; identity-confirm queries combine the candidate with context
   (channel / show / title, e.g. `All Ears English co-host Lindsay`); quote-attribution queries put the sentence in double quotes. Every query goes
   through `SearchRouter.search(..., job_id=…)` (budget + cache apply). Hits are numbered globally `web:1…web:n` in call order and returned in the
   stage output (`hits: [{id, url, title, snippet, text, provider, query}]`).
3. **Claim judge** (`verify_judge.md`, json mode): per claim → `Verification{target:"claim:<id>", verdict, confidence, rationale, sources[{url,
   title, snippet, evidence_id}]}`; the judge sees the claim, its transcript evidence lines and the hits inside `wrap_data` blocks and is told web
   text is untrusted data. Deterministic rules after the LLM: a non-`unverified` verdict must cite ≥ 1 `web:` id that exists (else forced
   `unverified`); `supported`/`contradicted` with confidence > 0.8 needs ≥ 2 sources from **different registrable domains** (else confidence capped
   at 0.6); unknown ids dropped.
4. **Identity web step** (`identity_web.md`, json mode): for identity-confirm targets → `{label, candidate, full_name|null, supported: bool,
   web_ids}`; for quote attribution → `{label, attributed_to|null, web_ids}`. Deterministic checks: `full_name` must start with / contain the
   candidate's name tokens and appear in ≥ 2 hits from different domains; attribution needs ≥ 2 hits from different domains naming that person.
   Then call the identity fusion with the extra `web` sources (docs/04 §8 steps 5–6: confirm +0.15 and full-name expansion; attribution = 0.5
   candidate, never promoted alone, info flag) and write the refined `speakers` + flags into the verify output.
5. **Stage `verify`**: skipped per plan or when no provider is configured (reason `"no search provider"`); output
   `{verifications, speakers (refined), flags, hits, queries_used, cost_usd}`. Assemble: `report.verification = verifications`, speakers from verify
   when present, web hits → `build_evidence_index(web_hits=…)`, and the existing validator enforces the web-id rules again.
