## Requirements
1. `prepare_schema` raises `ValueError("reserved field name: …")` when the **wire** name of any property (alias if set, else field name) is one of
   `type, items, properties, enum, format, required, default, const, anyOf, oneOf, allOf, $ref`. Pydantic aliases are the escape hatch: a report model
   field `type` is declared with `validation_alias="entity_type"`-style aliasing so the LLM sees `entity_type` and our JSON keeps `type`. Make
   `call_tool` validate with `by_alias`/`by_name` handled correctly (`model_validate` with `validate_by_alias=True, validate_by_name=True` as
   supported by pydantic 2.14 — check with context7) and test one aliased model end to end.
2. Evidence normalisation in `coerce`: for any array property whose name is `evidence` or ends with `_evidence`, or whose items carry
   `"x-evidence": true` in the schema, each string is replaced by the list of ids found with
   `(?:seg|meta|web|vp|caption|hint):[A-Za-z0-9_.\-]+` (flattened, de-duplicated, order kept); strings with no id are dropped.
3. `llm/prompts/__init__.py`: `render_transcript_lines(segments) -> str` producing `[seg:12] S2 03:14.2 | text` (speaker `S?` when unknown,
   `mm:ss.s`, `h:mm:ss.s` past one hour), and `render_metadata(meta: Mapping[str, str]) -> str` producing `[meta:title] …` lines (values passed
   through `wrap_data` rules: no `<<<`/`>>>`).
